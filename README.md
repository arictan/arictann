# Sushi Stack

A one-tap stacking game for iOS and Android. A layer of rice, fish or nori slides back and forth; tap to drop it.
Overhang gets sliced off, perfect drops build combos, and every finished roll serves a customer's order.

The game is written in TypeScript on an HTML5 canvas and packaged as a native app with
[Capacitor](https://capacitorjs.com). One codebase produces both the App Store build (`ios/`) and the Play Store build (`android/`).
See [GAME_DESIGN.md](GAME_DESIGN.md) for the design, and [PRIVACY.md](PRIVACY.md) for a privacy policy you can host.

## Play it now (in a browser)
```bash
npm install
npm run dev        # open the printed URL; use your phone on the same Wi-Fi to test touch
```

## Run on a device
```bash
npm run android    # builds the web code, syncs it, and opens Android Studio → press Run
npm run ios        # same for Xcode (macOS only) → choose your team under Signing & Capabilities → Run
```
After changing anything in `src/`, run `npm run sync`. To change the icon or splash, replace the PNGs in `assets/` and run `npm run assets`.

## Publishing checklist

### 0. Before your first upload
- [ ] **Pick your app ID.** Set `appId` in `capacitor.config.ts`, for example `com.yourname.sushistack`. Also change it in
      `android/app/build.gradle` (`namespace` and `applicationId`), in `android/app/src/main/res/values/strings.xml`, and in the iOS
      bundle identifier in Xcode. Once you publish, the ID **cannot be changed**.
- [ ] **Host the privacy policy.** Both stores require a public URL. GitHub Pages works: publish `PRIVACY.md` and add your email to it.
- [ ] **Screenshots and trailer are ready** in `store/` (see [store/LISTING.md](store/LISTING.md) for sizes and the listing texts in English and Turkish).
- [ ] **Run the device test plan** ([docs/DEVICE_TEST_PLAN.md](docs/DEVICE_TEST_PLAN.md)) on real phones: haptics, sound, camera, notifications and purchases can't be tested in a browser.
- [ ] **Answer the age-rating questionnaire** with [docs/AGE_RATING.md](docs/AGE_RATING.md).
- [ ] **Bump the version for every release.** Android uses `versionCode` and `versionName` in `android/app/build.gradle`. iOS uses Version and Build in Xcode.

### 1. Google Play (Android)
1. Create a [Play Console](https://play.google.com/console) developer account. There is a one-time $25 fee and an identity check.
2. Create an upload key. Do this once, and **back the key up**, because losing it makes updates painful:
   ```bash
   keytool -genkey -v -keystore sushi-stack-upload.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
   ```
3. In Android Studio, go to **Build → Generate Signed App Bundle → Android App Bundle (.aab)** and use that key.
4. In the Play Console, create the app, then fill in the store listing (icon 512×512, feature graphic 1024×500, phone
   screenshots), the content rating questionnaire, the target audience, and **Data safety**. Data safety, with the build as it is:
   * **Device or other IDs: collected** (by the AdMob SDK, for ads delivery, fraud prevention and analytics; not shared for
     personalization, since ads are non-personalized). If you remove ads, this goes away.
   * **Purchase history: collected** (by RevenueCat, to confirm purchases), once purchases are live.
   * **App activity / app interactions:** only if you connect an analytics service to the "Share anonymous stats" switch
     (it's optional for the player, so mark it optional).
   * **With the online server on:** user IDs (the random player ID), "Other user-generated content" (chef name) and game
     progress (scores, cloud backup). Data is encrypted in transit (HTTPS) and players can delete it in the app.
   * Everything else (location, contacts, photos, camera, audio): not collected.
5. Upload the `.aab` and choose **Play App Signing**. New *personal* accounts must first run a **closed test with
   at least 12 testers for 14 days** before they can release to production, so plan for that.

### 2. Apple App Store (iOS)
Apple builds require a Mac with Xcode.
1. Join the [Apple Developer Program](https://developer.apple.com/programs/) ($99 per year).
2. In [App Store Connect](https://appstoreconnect.apple.com), create the app with the same bundle ID.
3. In Xcode, select your team under *Signing & Capabilities*, choose **Any iOS Device**, and run **Product → Archive**, then **Distribute App → App Store Connect**.
4. Fill in the listing: screenshots for the 6.9" iPhone (1320×2868) and for the 13" iPad, since iPad is supported. To skip the iPad screenshots,
   set *Supported Destinations* to iPhone only. Also set the age rating, the privacy policy URL, and
   **App Privacy** to match the Data safety list above (Identifiers → Device ID, used for third-party advertising and
   not linked to the user, **not** used for tracking; Purchases, once live). Encryption export compliance is already answered: `ITSAppUsesNonExemptEncryption = NO`.
5. Test the build through TestFlight, then submit it for review.

### Ads (AdMob) — test mode until you set it up
The game ships with Google's **public test** ad IDs, so test ads play on phones and nothing earns money yet. Before release:
1. Create an app and a **Rewarded** ad unit at https://admob.google.com.
2. Put your rewarded ad unit IDs in `src/monetize.ts` (`REWARDED_AD_ID`) and set `ADS_TESTING = false`.
3. Replace the test **app IDs** in `android/app/src/main/AndroidManifest.xml` (`com.google.android.gms.ads.APPLICATION_ID`) and `ios/App/App/Info.plist` (`GADApplicationIdentifier`).
4. Ads are **non-personalized** and Google's consent form (UMP) is shown where required. Publish a GDPR message in AdMob
   (Privacy & messaging) or no form appears. Details, and how to switch to personalized ads: [docs/AGE_RATING.md](docs/AGE_RATING.md).

### In-app purchases (RevenueCat) — test mode until you set it up
In the browser and in dev builds, purchases are simulated, and the screen says so. In a release build without setup, purchase buttons explain that purchases aren't available yet. To go live:
1. Create these products in App Store Connect and the Google Play Console: `sushistack.starter` (non-consumable), `sushistack.vip.monthly` (auto-renewing subscription), `sushistack.piggy` (consumable), `sushistack.pass.premium` (non-consumable, or one per season) and `sushistack.restaurant.monthly` (auto-renewing subscription: the Restaurant Pass).
2. Create a project at https://www.revenuecat.com, connect both stores, and add the products.
3. Paste your RevenueCat public SDK key into `REVENUECAT_API_KEY` in `src/monetize.ts`.
4. Consider restoring purchases and handling the VIP subscription status from RevenueCat entitlements (the game currently grants 30 days of VIP or Restaurant Pass per purchase).

### In-app events
See [store/IN_APP_EVENTS.md](store/IN_APP_EVENTS.md) for ready-made event cards (images + copy) for the App Store and Google Play.

### 3. Optional: online features
**Our own server** ([server/README.md](server/README.md)) runs the Daily Roll board, friends' scores, the Tower of the
World, the country cup and cloud backup. Deploy it, then set `serverUrl` in remote config: no app update needed. Until
then, those screens use labelled simulated players.

**Game Center / Play Games leaderboards** are separate and optional. To add them, first set up the store accounts:
- **iOS:** enable *Game Center* for the app in App Store Connect, create a leaderboard (for example `best_height`), and add the Game Center capability in Xcode.
- **Android:** create a Play Games Services project in the Play Console, with a leaderboard of the same purpose.
- Then add a Capacitor game-services plugin and register it with `setOnlineServices()` in `src/services.ts`. Scores are already submitted at the end of every run, to the board IDs listed in `BOARDS`.

### Store images and trailer
`store/ios/` has eight 1320×2868 screenshots (iPhone 6.9"; App Store Connect scales them for smaller iPhones),
`store/android/` eight 1080×1920 phone screenshots, `store/feature-graphic.png` the 1024×500 Play feature graphic and
`store/trailer.mp4` a 29-second 1080×1920 trailer (App Store app preview; upload it to YouTube for Play's promo video).
They're rendered from the real game with `tools/store/` scripts; regenerate them after big visual changes.

### Analytics, remote config and tuning
Nothing leaves the device unless the player turns on **Settings → Share anonymous stats** (off by default). To receive
those events, register a sink in `src/analytics.ts` (e.g. Firebase Analytics) or set `ANALYTICS_ENDPOINT`. The funnel
events (install, first-day steps, first chef, restaurant, day 2, day 7, session end) are listed in `FUNNEL`.
To tune balance without an update, host a JSON file with keys from `DEFAULTS` in `src/config.ts` and set
`REMOTE_CONFIG_URL`. The economy and difficulty were tuned with simulations: [docs/ECONOMY.md](docs/ECONOMY.md),
[docs/DIFFICULTY.md](docs/DIFFICULTY.md). The plan for a first release in a few countries is in [docs/SOFT_LAUNCH.md](docs/SOFT_LAUNCH.md).

### Saves, backups and cloud save
Progress is versioned (`SAVE_VERSION` in `src/safety.ts`, with step-by-step migrations) and backed up on the device once
a day (two days kept; restore from Settings → Diagnostics). Players can move progress with a save code, or, with the
server on, a **cloud backup** (an ID + PIN). Bump `SAVE_VERSION` and add a migration whenever saved data changes shape.

### App icon with the mascot
`store/mascot-icon.png` is a 1024×1024 icon of Sake-chan. To use it, copy it over `assets/icon-only.png` (and use it
as `assets/icon-foreground.png` on a plain background) and run `npm run assets`.

### Camera (Table mode)
Table mode asks for the camera only when the player turns it on. The Android `CAMERA` permission (camera optional) and the
iOS `NSCameraUsageDescription` text are already set. The image is shown, never recorded or uploaded; say so in the store
privacy forms ("camera: not collected").

### Home-screen widget and Live Activity
The game sends a small snapshot (restaurant, tip jar, calendar day, level and chef) through `src/widget.ts`. The native side isn't in
`ios/` or `android/` yet. Follow [native/README.md](native/README.md) to add the WidgetKit extension, the Live
Activity and the Android AppWidget, then test on a real device. Until then the bridge does nothing.

### Notifications
The game schedules local reminders with `@capacitor/local-notifications`: one daily reminder, the full tip jar, the next Rush Hour and a dish that's finished cooking (each replaces its previous one, so they never pile up). No server is involved. On Android 13+ and on iOS, the permission prompt appears after the player claims their first daily gift.

### Store listing
Name, subtitle, short and full description, keywords and "what's new", in English and Turkish, all within the
stores' limits: [store/LISTING.md](store/LISTING.md).

### Testing
* `node server/test.mjs`: server tests.
* `tools/sim/`: difficulty, economy and performance bots (see its README).
* Settings → Diagnostics on a phone: frame time, saved data, errors, and a button for every phone feature (haptics,
  sound, tilt, camera, reminders, widget). Use it with [docs/DEVICE_TEST_PLAN.md](docs/DEVICE_TEST_PLAN.md).
